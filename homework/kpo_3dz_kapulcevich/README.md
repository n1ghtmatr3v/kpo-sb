# Антиплагиат: микросервисное приложение

Проект реализует серверную часть системы проверки контрольных работ в соответствии с требованиями домашнего задания. Стек — **Java 17 + Spring Boot 3**, сервисы упакованы в Docker и собираются через `docker-compose`.

## Архитектура
- **API Gateway (порт 8080)** — единственная точка входа клиента. Принимает загрузку работ и сразу инициирует анализ. Отдает агрегированные ответы и список отчетов по заданию.
- **File Storage Service (порт 8081)** — принимает файлы, рассчитывает SHA-256 хеш, фиксирует метаданные (кто, когда, какое задание), хранит файлы на диске и отдает как метаданные, так и бинарное содержимое. БД: H2 в режиме in-memory.
- **File Analysis Service (порт 8082)** — получает идентификатор загрузки, запрашивает метаданные и содержимое у хранилища, формирует отчет о заимствованиях и строит ссылку на облако слов. БД: H2 в режиме in-memory.

Обмен между микросервисами синхронный через REST. API каждого сервиса документировано через встроенный Swagger UI (`/swagger-ui.html`).

## Алгоритм обнаружения плагиата
1. File Storage Service рассчитывает SHA-256 хеш содержимого и хранит его вместе с метаданными.
2. File Analysis Service при запуске анализа запрашивает:
   - метаданные проверяемой работы `/files/{id}/metadata`;
   - список всех работ по тому же заданию `/files/assignments/{assignment}`.
3. Среди полученных метаданных выбирается более ранняя работа другого студента с тем же хешем. Если совпадение найдено — отчет помечается как плагиат с указанием идентификатора конфликтной сдачи, иначе плагиат отсутствует.
4. Для визуализации текста строится ссылка на облако слов (QuickChart Word Cloud API) на основе частот слов текущего файла.

## Пользовательские сценарии
1. **Загрузка работы и запуск анализа (студент):**
   - `POST /api/submissions` (Gateway, multipart: `file`, `studentName`, `assignmentName`).
   - Gateway пересылает файл в File Storage Service → получает идентификатор → синхронно вызывает File Analysis Service для генерации отчета.
   - Клиент получает агрегированный ответ: метаданные сохраненной работы + итоговый отчет.
2. **Получение аналитики по заданию (преподаватель):**
   - `GET /api/assignments/{assignment}/reports` (Gateway) возвращает JSON со всеми отчетами для указанного задания, включая флаг плагиата и идентификатор конфликтной работы, если найден.

## Запуск через Docker Compose
```bash
docker compose build
docker compose up
```
Сервисы будут доступны на `http://localhost:8080` (Gateway), `http://localhost:8081` (Storage), `http://localhost:8082` (Analysis).

## Локальный запуск из исходников
```bash
mvn clean package -DskipTests
java -jar gateway/target/gateway-*.jar &
java -jar file-storage-service/target/file-storage-service-*.jar &
java -jar file-analysis-service/target/file-analysis-service-*.jar &
```

## Swagger UI
- Gateway: `http://localhost:8080/swagger-ui.html`
- File Storage Service: `http://localhost:8081/swagger-ui.html`
- File Analysis Service: `http://localhost:8082/swagger-ui.html`

## Построение облака слов
File Analysis Service извлекает текст файла, рассчитывает частоты слов и формирует URL QuickChart вида `https://quickchart.io/chart?c=...`. Ссылка включена в ответ отчета, что соответствует критерию на 10 баллов.

## Обработка ошибок
- Валидация полей `studentName` и `assignmentName` на пустые значения.
- В случае отсутствия работы/отчета сервисы возвращают ошибку 400/404 (через стандартные исключения Spring).
- При недоступности микросервисов клиент получит стандартный HTTP-код ошибки, демонстрируя отказоустойчивость при падении части системы.
